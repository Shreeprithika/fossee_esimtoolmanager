1. Executive Summary & Problem Formulation

1.1 Background

eSim (formerly known as Oscad) is an open-source Electronic Design Automation (EDA) suite developed by FOSSEE at IIT Bombay. It enables schematic creation, PCB layout, analog/digital/mixed-signal circuit simulation, and model parameter extraction.

To provide these capabilities, eSim relies on several third-party software packages and toolchains:

  • Ngspice: Mixed-signal SPICE circuit simulation engine.
  • KiCad (Eeschema, Pcbnew): Schematic capture, netlist generation, and PCB routing.
  • GHDL: VHDL-2008 simulation compiler used in NgVeri for mixed-signal co-simulation.
  • Verilator: SystemVerilog compiler for high-speed digital models.
  • Makerchip / SandPiper-SA: Cloud and desktop TL-Verilog compiler and simulation harness.
  • C/C++ Build Toolchain (GCC/Clang, Make): Used to compile digital wrappers and mixed-signal simulation models.
  • Python Scientific Stack: matplotlib, numpy, scipy, PyQt5/PyQt6, ply.

    • 1.2 The Problem

    Manual installation and maintenance of these diverse external tools present severe operational bottlenecks for students, researchers, and engineers: 1. Dependency Hell & Version Mismatches: Incompatible tool versions (e.g., KiCad 5 netlist syntax vs. KiCad 8/9; outdated Ngspice lacking modern PSPICE/BSIM-CMG models). 2. Environment Variable & PATH Friction: Tools installed in non-standard directories fail silently because PATH, NGSPICE_PATH, or KICAD_PATH are unset or misconfigured. 3. Cross-Platform Discrepancies: Linux requires apt/dnf package scripts; Windows requires Windows Package Manager (winget), Chocolatey, or standalone portable binaries; macOS requires Homebrew. 4. Lack of Centralized Diagnostic & Update Mechanism: When a circuit simulation fails, users cannot easily distinguish between a circuit design bug and a broken underlying toolchain dependency.

    1.3 Proposed Solution

    The eSim Automated Tool Manager (eSim-ATM) is a modular, extensible, cross-platform software system that automates the entire lifecycle of eSim's external toolchain:
  • Pre-flight Diagnostic ("eSim Doctor"): Comprehensive scanning of binaries, versions, Python modules, and environment variables.
  • Automated Installation Engine: Multi-backend installation (Native Package Managers + Direct Zero-Privilege Portable Downloads).
  • Automated Update & Rollback System: Upstream version tracking (GitHub Releases API, PyPI API) with automatic pre-upgrade directory backup and rollback.
  • Unified Configuration & Environment Export: Automatic generation of .esimrc, config.ini, Windows .bat launchers, Linux .sh loaders, and persistent environment variable scripts.
  • Dual User Interface: High-productivity CLI with formatted tables and colorized badges, alongside a modern, responsive Graphical User Interface (GUI).
  • Audit Logging: Structured JSON Lines (.jsonl) and rotating text logs for full traceability of all actions and errors.

    3. Detailed Component Breakdown

    3.1 Data & Manifest Layer

    #### manifest.json Acts as the central declarative repository of tool knowledge. Adding a new external tool to eSim (e.g. OpenLane, SkyWater PDK, Xschem) requires zero code changes—only a new JSON block defining:
  • name, category, description
  • min_version, recommended_version
  • binary: Platform-specific executable names (ngspice.exe vs ngspice)
  • version_check: Command-line arguments (-v, --version) and Regex patterns
  • env_var: Target environment variable (e.g. NGSPICE_PATH)
  • install: Installation rules for Windows, Linux (apt, dnf, pacman), macOS (brew), and portable direct URLs
  • upstream: Upstream release monitoring endpoint (GitHub repository, PyPI package, or HTTP RSS)

    • 3.2 Core Services Layer

    1. PlatformDetector (core/platform_detect.py): * Normalizes OS into windows, linux, darwin. * Queries operating system release and distribution (/etc/os-release on Linux, platform.version() on Windows). * Detects architecture (x86_64, arm64). * Probes system PATH for active package managers: winget, choco, apt-get, dnf, pacman, brew, pip. * Checks administrator / root privilege (ctypes.windll.shell32.IsUserAnAdmin() on Windows, os.geteuid() == 0 on POSIX).

    2. ConfigurationManager (core/config.py): * Manages user configuration in esim_manager_config.json. * Tracks customizable installation root (install_dir), backup location (backup_dir), preferred package manager (auto, winget, apt, direct), and custom tool path overrides. * Exports multi-format environment profiles: * .esimrc: Standard JSON profile. * config.ini: Traditional INI configuration parsed by eSim core. * setup_esim_env.bat: Batch script configuring PATH and tool variables for Windows terminal sessions. * setup_esim_env.sh: Shell script for Linux/macOS sessions.

    3. ActionAuditor & CustomFormatter (core/logger.py): * Dual logging architecture: * File Logger: Detailed debug trace written to esim_tool_manager.log with timestamp, log level, and component name. * Audit Trail: Machine-readable JSONL records in esim_actions.jsonl tracking user actions (INSTALL_COMMAND, BACKUP, ROLLBACK, UPGRADE_TOOL, CONFIGURE_ENVIRONMENT), success/failure states, and duration.

    3.3 Business Logic Layer

    1. DependencyChecker (modules/dependency_checker.py): * Multi-stage Path Resolution: Searches user custom overrides, system PATH, tool manager's portable directory, and standard vendor installation directories (C:\Program Files\KiCad, /usr/bin/ngspice, etc.). * Execution & Version Parsing: Invokes candidate binaries with strict timeouts (preventing hanging processes). Parses semantic versions via regular expressions. * Robust Version Comparison: Implements zero-padded integer tuple comparison (compare_versions), handling semver formats (42.0.1, 8.0-rc2, 4.038). * Python Runtime Inspection: Dynamic inspection of matplotlib, numpy, scipy, PyQt5/PyQt6, and ply via importlib.util and importlib.metadata. * eSim Doctor Engine: Produces aggregated DiagnosticReport classifying each dependency as OK, OUTDATED, NOT_FOUND, or INCOMPATIBLE.

    2. ToolInstaller (modules/installer.py): * Native Package Manager Integration: Formulates silent, unattended commands for winget, choco, apt, dnf, pacman, brew, and pip. * Direct Portable Download Engine: * Chunked streaming via urllib.request with real-time download progress callbacks. * Automated extraction of .zip, .tar.gz, and .tar.xz archives. * Automatic discovery of internal executable binaries and permission setting (chmod 0755 on POSIX). * Automatic path registration into ConfigurationManager. * Dry-Run Mode (--dry-run): Simulates the exact commands and file locations without making system modifications.

    3. ToolUpdater (modules/updater.py): * Upstream Release Probing: Queries the GitHub Releases API (/repos/{owner}/{repo}/releases/latest) and PyPI JSON API to identify current latest versions. * Automated Pre-Update Backup: Creates a timestamped directory backup in backup_dir before modifying an existing installation. * Safety Rollback Engine: If an installation fails, the tool manager automatically removes the broken folder and restores the backed-up version, ensuring zero downtime.

    4. ToolConfigurator (modules/configurator.py): * Scans and aggregates all installed tool binary paths. * Updates environment variables in the active session (os.environ). * Exports .esimrc, config.ini, setup_esim_env.bat, and setup_esim_env.sh. * Generates persistent system scripts (apply_persistent_env.ps1 for Windows, apply_persistent_env.sh for Linux) to configure user environment variables permanently.

    5. Security, Robustness, and Extensibility

    5.1 Security Considerations

  • Unattended Execution Safety: All package manager commands (winget, apt, choco) use exact explicit IDs and official repositories to prevent malicious package substitution.
  • Privilege Separation: The manager defaults to user-space portable installations (%LOCALAPPDATA%\eSim_Tools or ~/.esim/tools) whenever administrative privileges are absent, avoiding unauthorized system tampering.
  • Timeout Guards: All subprocess calls (e.g. checking binary versions) enforce strict 5-second timeouts to eliminate hanging threads caused by interactive prompt stalls.

    • 5.2 Error Handling & Logging

  • Graceful Degradation: If GUI modules fail to initialize or the system lacks a graphical display (e.g. headless CI/CD server), the CLI seamlessly takes over without application termination.
  • Audit Trail: Every invocation is appended to esim_actions.jsonl with ISO 8601 timestamps, allowing auditability during grading and debugging.

    • 5.3 Extensibility

    Adding a future simulator (such as Xschem, Magic VLSI, or OpenLane) requires only adding a new entry to manifest.json. The entire scanner, installer, updater, configuration generator, and GUI render the new tool automatically with zero modifications to the core engine.
